# Tech Stack — QuizMaster

## Frontend

| Параметр | Значення |
| :--- | :--- |
| Фреймворк | React 18 |
| Збірка | Vite |
| Стан застосунку | Redux Toolkit |
| Маршрутизація | React Router |
| Стилізація | CSS |
| Запити до бекенду | Axios |
| Якість коду | ESLint + Prettier |
| Слайдери | Swiper |

**Чому обрали:
- React + Vite: збирає проєкт і запускає dev-сервер. Швидший за Create React App, який уже не підтримується.
- CSS: Стилі ізольовані по компонентах, без конфліктів назв класів. Глобальні змінні в `:root` (кольори, шрифти) і `@font-face` відповідають вимогам ТЗ. Дозволяють налаштувати кастомні брейкпоінти за ТЗ (до `375px` — fluid, `375px` — mobile, `768px` — tablet, `1440px` — desktop).
- React Router: Стандарт для односторінкових додатків (SPA) з підтримкою декларативної маршрутизації та зручним керуванням навігацією.
- Redux Toolkit: Надійний та стандартизований інструмент для ефективного керування глобальним станом застосунку з мінімальною кількістю бойлерплейт-коду.
- Axios: Запити до бекенду. З withCredentials: true браузер сам надсилає httpOnly cookie. Окремий інстанс (api.ts) з базовим URL зручно використовувати скрізь.
- ESLint + Prettier: Єдиний стиль коду для команди з трьох людей.
- Swiper: Слайдери для `BaseQuizList` (планшет і мобільний) та `Reviews`.

## Backend

| Параметр | Значення |
| :--- | :--- |
| Мова | JavaScript (Node.js) |
| Фреймворк | Express.js |
| Документація API | Swagger UI (`swagger-ui-express`) |
| База даних / ODM | MongoDB + Mongoose |
| Автентифікація | JWT у httpOnly cookie + bcrypt |
| Валідація | Joi |

Чому обрали:
- Express.js: Мінімалістичний та перевірений часом фреймворк, чудово комбінується з будь-якими middleware для обробки помилок, CORS та валідації.
- JWT + bcrypt: Токен генерується при логіні та передається клієнту через httpOnly cookie. Усі захищені ендпоінти читають його з cookie, а не з заголовка `Authorization`, як вимагає ТЗ. Паролі зберігаються у вигляді хешів (bcrypt).
- Swagger: Пряма вимога ТЗ мати інтерактивну документацію за окремим маршрутом (`/api-docs`).
- MongoDB (Atlas) + Mongoose: ТЗ оперує поняттям "колекції", а документна модель добре підходить для тестів з вкладеними даними (середній рейтинг, лічильник проходжень). Сутності `User`, `Quiz`, `Question`, `Review` пов'язані посиланнями (один-до-багатьох: тест має багато питань). Mongoose дає схеми, валідацію на рівні моделей і зручний клієнт запитів.
- Joi: Валідація вхідних даних на сервері, бо клієнтській валідації довіряти не можна. Разом із `http-errors` і глобальним error-handler дає коректні HTTP-статуси (400, 401, 404, 500) та зрозумілі повідомлення для клієнта.

## Інфраструктура

| Параметр | Значення |
| :--- | :--- |
| База даних | MongoDB Atlas |
| Хостинг frontend | Vercel / Netlify |
| Хостинг backend | Render / Railway |
| Хмарне сховище | Cloudinary |

Чому обрали:
- MongoDB Atlas: Керована хмарна база з безкоштовним тарифом, достатнім для навчального проєкту, і простим підключенням до Mongoose.
- Vercel: Безшовна інтеграція з GitHub, автоматичний деплой при злитті в гілку `main`, швидкий CDN.
- Render/Railway: Надають безкоштовний/тестовий хостинг для Node.js сервісів.
- Cloudinary: Спеціалізований сервіс для завантаження, оптимізації та зберігання аватарів користувачів через API без перевантаження сервера статикою.
